Nex Core host-local API — 0.1.0

Development host-local HTTPS API v1, independent of Controller sessions and outages. Narrow appliance deployment and owned local power recovery; a local VM console WebSocket; no generic VM creation or network editor. Core outbound protocol and signed appliance format/protocol version 1 only. Deploy matching development components; no mixed-version upgrade window is promised.

POST /api/local/v1/session

Sign in to this host

Authenticates only username root against the host operating-system password using PAM authentication and account checks, and validates browser origin. Use the root password set during Nex Core installation, or its current value after an OS password change. Locked or expired accounts/passwords and authentication-service failures fail closed, including the five-second helper timeout. Sets __Host-nex_local_session with Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain. Each login creates a new session; at most 64 active sessions per service. Sessions expire after 30 minutes without an authenticated mutation and eight hours absolutely; GET/HEAD polling does not renew them. Legacy unprefixed cookies are not accepted; sign in again after upgrade. The former separate local admin account and saved credential files are not accepted; there is no fallback. Upgrades require matching local service, PAM helper/configuration and web assets. Root password changes affect subsequent logins; existing sessions remain valid until logout, expiry or service restart. Controller admin credentials and Core protocol v1 are unchanged. Local process restart invalidates its in-memory sessions. Login admission permits at most five valid-length attempts per one-minute actual peer-IP window, two concurrent password checks per service, and 4096 tracked peers. Forwarded client-IP headers are ignored. Login returns 429 when rate/concurrency/table or 64-session capacity is exhausted; bounded retries must not create an unbounded loop.

POST /api/local/v1/pool/join

Join this enrolled Core to a pool

Authenticated local root session, same HTTPS Origin and X-CSRF-Token required. This is the host-local recovery path; the ordinary workflow is the Controller's POST /api/v1/pools/{id}/members, which needs no CSR or offer handling by the operator. This Core must already be enrolled. It runs the same join precheck the Controller command path runs (enrolled, no managed VMs, no non-local storage, currently the master of its own single-host pool), validates the bare HTTPS master_url, pinned pool_ca_pem and opaque one-use offer, pauses its outbound agent, performs the Core-to-Core TLS 1.3 CSR exchange, then resumes reporting with the master-owned membership. The Controller may display/pass the offer but does not participate in peer authentication or keep membership intent. The local request body and offer are not echoed. A refusal before the exchange, a used or expired offer, an identity mismatch or a Core already belonging to another pool is 409 and leaves local membership unchanged; retry requires a new offer. Once the peer exchange succeeds the response is 200 and reports the stage reached in join, including stage rehomed with status needs_attention when this host is a member but its local resource rehome has not finished: Core retries the remaining stages itself. A 409 therefore means the host did not join; it never means an unfinished rehome. There is no cancellation after peer acceptance: reconcile membership inventory, or read GET /api/local/v1/pool, before retrying an interrupted browser reply.
