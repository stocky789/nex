Nex Core host-local API — 0.1.0

Development host-local HTTPS API v1, independent of Controller sessions and outages. Narrow appliance deployment and owned local power recovery; a local VM console WebSocket; no generic VM creation or network editor. Core outbound protocol and signed appliance format/protocol version 1 only. Deploy matching development components; no mixed-version upgrade window is promised.

Download OpenAPI JSON. This reference works offline; examples do not execute requests.

POST /api/local/v1/session

Sign in to this host

Authenticates only username root against the host operating-system password using PAM authentication and account checks, and validates browser origin. Use the root password set during Nex Core installation, or its current value after an OS password change. Locked or expired accounts/passwords and authentication-service failures fail closed, including the five-second helper timeout. Sets __Host-nex_local_session with Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain. Each login creates a new session; at most 64 active sessions per service. Sessions expire after 30 minutes without an authenticated mutation and eight hours absolutely; GET/HEAD polling does not renew them. Legacy unprefixed cookies are not accepted; sign in again after upgrade. The former separate local admin account and saved credential files are not accepted; there is no fallback. Upgrades require matching local service, PAM helper/configuration and web assets. Root password changes affect subsequent logins; existing sessions remain valid until logout, expiry or service restart. Controller admin credentials and Core protocol v1 are unchanged. Local process restart invalidates its in-memory sessions. Login admission permits at most five valid-length attempts per one-minute actual peer-IP window, two concurrent password checks per service, and 4096 tracked peers. Forwarded client-IP headers are ignored. Login returns 429 when rate/concurrency/table or 64-session capacity is exhausted; bounded retries must not create an unbounded loop.

POST /api/local/v1/vms/{id}/actions

Request local appliance power action

Explicitly select the resident VM UUID. Only locally owned eligible appliances can be controlled; arbitrary guests and ambiguous ownership are refused. start, graceful shutdown and force-stop are supported. The client confirms the selected VM/action; no typed hostname is required and the legacy confirmation field is ignored. Persist a request_id before submission. Reusing the same ID/input observes the existing journal; interrupted or ambiguous effects are not automatically repeated. A 202 response is not proof of final power state: inspect the operation and fresh VM inventory. Controller outage neither stops guests nor permits takeover. Graceful shutdown returns stage shutdown_requested when the command is accepted; refresh VM inventory to establish actual shutdown. Power request journals are reconciled by resubmitting the same request; deployment polling routes do not expose power operations.

POST /api/local/v1/deployments

Deploy this host's Controller appliance

Persists one deployment intent before asynchronous work. Set a stable request_id, explicit configured local storage/bridge, resources, network_mode (static or dhcp), first Site and Controller password. Zero or omitted resource fields use 2 vCPUs, 4096 MiB and 32 GiB. Repeating identical normalized input returns the same operation; different input or a second deployment conflicts. The worker verifies the signed appliance, creates an independent disk and cloud-init seed, starts the original VM, verifies Controller TLS and completes enrollment/adoption. Poll the operation; guest boot is not completed handoff. Interrupted VM effects require observation and never recreate the appliance. DHCP waits up to five minutes at waiting_for_network for one usable IPv4 address from the guest agent on the exact owned VM/MAC; missing or ambiguous addresses produce needs_attention and can be retried. controller_url is absent until an address is found. The discovered IP is verified using the per-instance Controller certificate and hostname before handoff. DHCP requires matching rebuilt host and appliance components; omitted network_mode preserves static clients.

POST /api/local/v1/enrollment

Push an enrollment token to this host

Lets the Controller enroll this host over its existing local session instead of the manual nex-core-agent enroll step. controller_url must be a bare HTTPS origin (no userinfo, path, query or fragment); ca_pem must contain at least one certificate; token must be 1-256 bytes with no control characters; replace_host, when set, is an existing revoked host id being replaced and must be at most 128 characters. Enrollment attempts on this host are serialized; a retried request queues rather than racing the embedded agent's on-disk identity. Already enrolled with a different replace_host returns 409 with the current host_id and changes nothing. On success the embedded agent persists its new identity, starts reporting to the Controller, and the response host_id also appears from GET /api/local/v1/host. The Controller's rejection of the token (expired, already used, wrong site) surfaces as 502 and leaves this host unenrolled; retrying with a fresh token is safe. The token and ca_pem are never logged or echoed back.
