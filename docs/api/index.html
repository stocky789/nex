Nex Controller and Core API — 0.1.0

Implemented development API for administrator inventory, enrollment, durable operations, appliance adoption and managed-VM creation. Capability-gated storage/network registration, bounded ISO transfer and stopped-VM provisioning use outbound authenticated Core reports. Browser VM consoles use single-use tickets, an outbound host tunnel and a same-origin WebSocket. Central VM power requests (start, shutdown, reboot, force-stop) are durable host operations.

vm-media

{
  "transport": "POST /api/v1/agent/report response.commands",
  "capability": "vm-media-v1",
  "payload": {
    "$ref": "#/components/schemas/VMMediaRequest"
  },
  "result": {
    "$ref": "#/components/schemas/Result"
  },
  "semantics": "Insert a verified ISO into, or eject media from, the named VM's CD drive on this host with one libvirt change-media (live and persistent). Insert attaches an empty CD drive first when the domain has none; eject on a drive that is already empty (checked against the live definition of a running VM) succeeds without any libvirt call and never attaches a drive. The resolved media path and the changing-media stage are journaled in one write immediately before the change, so an interruption before that write is simply re-applied and one after it is reconciled by observing the domain: succeeded when the drive holds the requested media (or none, for eject), otherwise needs_attention. Core records only media_id in the VM's journaled specification; boot order values are never rewritten because change-media leaves every device's bootindex as it is."
}

POST /api/v1/session

Sign in as administrator

Validates existing administrator credentials and browser origin. Sets __Host-nex_session with Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain. Each login creates a new session; at most 64 active sessions per service. Sessions expire after 30 minutes without an authenticated mutation and eight hours absolutely; GET/HEAD polling does not renew them. Legacy unprefixed cookies are not accepted; sign in again after upgrade. Existing password hashes remain valid; new administrator bootstrap passwords must be nonempty valid UTF-8, at most 1024 UTF-8 bytes, without CR, LF or NUL; there is no minimum length or complexity rule. Login admission permits at most five valid-length attempts per one-minute actual peer-IP window, two concurrent password checks per service, and 4096 tracked peers. Forwarded client-IP headers are ignored. Login returns 429 when rate/concurrency/table or 64-session capacity is exhausted; bounded retries must not create an unbounded loop.
