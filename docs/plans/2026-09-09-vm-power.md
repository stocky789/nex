# Central VM power controls

Date: 2026-09-09
Status: implemented in Controller; verified in a disposable nested-KVM lab together with the console slice.

## Scope and decisions

project owner asked for start, stop and reboot buttons in the web GUI after the console slice made
the "start it on its host" caveat obvious. This delivers the Phase 2 power item from the
[platform plan](2026-09-08-nex-platform.md#2-one-host-vm-management) for Controller:
Start, Shut down (ACPI), Reboot (ACPI) and Force stop on the VM page, each a durable host
task reusing the managed command journal, replay and result flow. The host-local page keeps
its existing recovery-only power controls for the appliance it deployed; widening those is
a separate product decision.

Design (smallest change on the existing command path):

- One `vm-power` command with `{vm_id, pool_id, host_id, action}`; Core journals the stage
  before its single `virsh` call so an interruption is reconciled by observation, never by
  a second request. Start and force-stop are idempotent against the observed state.
- Controller stores the request through the same resource/operation tables as creation
  (`request_id` replay, audit, dispatch on the next report) and allows one in-flight power
  request per VM. Power requests are not pool-scoped settings, so nothing is re-adopted by
  a replaced Controller.
- The UI shows the observed state and freshness next to the controls, confirms every action
  except Start, and tells the operator that shutdown/reboot are requests the guest decides.

API impact: **new contract** — `POST /api/v1/vms/{id}/power`, the `vm-power` command and
capability `vm-power-v1`; recorded in the [API reference](../API.md#central-vm-power-requests)
and OpenAPI contract. Guide impact: **updated** — [Control VM power](../guide/vm-power.md),
guide navigation, and the console/creation pages' availability notes.

## Acceptance

- [x] Controller accepts only valid actions for a known VM on a fresh, capable host in the
      VM's pool; replays by `request_id`; refuses a second in-flight request per VM; audits.
- [x] Core issues exactly one libvirt request, is idempotent for start/force-stop, refuses
      paused or transitional guests, and reconciles both interruption points honestly.
- [x] Go, contract and documentation checks pass; both CI providers already run them.
- [x] Browser walkthrough: Start, Reboot (ignored by a boot menu) and Force stop from the
      Controller page against a running guest in a disposable nested-KVM lab.
- [x] Independent review of the implementation and evidence.

Evidence: [console QA report](../qa/console/checks.md).

## Out of scope

Stopped-VM editing and deletion, scheduled or bulk power actions, guest-agent based
shutdown confirmation, and host-local power for arbitrary guests.
