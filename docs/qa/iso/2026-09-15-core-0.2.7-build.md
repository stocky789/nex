# Nex Core 0.2.7 build and publication

Date: 2026-09-15. Same developer workstation and toolchain as the
[0.2.6 build](2026-09-15-core-0.2.6-build.md): the version resolved from the changelog
(`scripts/release-version.py --current --format both` → `0.2.7 0.2.7`), `bash installer/build.sh`
with `NEX_VERSION=0.2.7`, then `packaging/controller/build.py --source dist/nex-source.tar.gz
--version 0.2.7` for the Controller package from the same source archive the ISO embeds.

0.2.7 carries BUG-0195 (creating a VM or editing a stopped one no longer depends on memory free at
that moment; free memory is checked when the VM starts) together with the other work committed in
the same commit. Built from commit `d597e8f` with a clean tree; the tracked source still matched
that commit when the artifacts were checked.

## The fix is in the artifacts, not just the tree

- The Core package's `/usr/lib/nex/nex-core-local` executable contains the start-time refusal
  `insufficient available memory to start this VM`.
- The BUG-0195 regressions, the race suites and the documentation and privacy checks passed on the
  same change before it was committed; the native lab evidence is in the BUG-0195 ledger entry.

## Publication

Published by hand from the build workstation to the website host over SSH as the publishing
account, running the commands the release workflow runs: `sudo -n /usr/local/sbin/nex-apt-publish
<core-local.deb> <controller.deb>` for the signed APT archive, then `release-publish.py --iso <iso>`
for the download tree. Retention was `--keep 8`, so no earlier release was pruned; the tree holds
`0.1.6~alpha1`, `0.1.8`, `0.2.2`, `0.2.3`, `0.2.4`, `0.2.5`, `0.2.6` and `0.2.7`, with `latest`
pointing at `0.2.7`. The staging directory was removed.

Verified afterwards over public HTTPS, the same checks the workflow makes:

- `/apt/dists/nex/InRelease` → 200.
- `/apt/dists/nex/main/binary-amd64/Packages` → 200 and lists `nex-core-local 0.2.7` and
  `nex-controller 0.2.7`; both pool files return 200 with byte sizes equal to the built packages.
- `/downloads/0.2.7/nex-core-0.2.7-amd64.iso.sha256` → 200 and equals the built ISO digest.
- `/downloads/latest/` serves `nex-core-0.2.7-amd64.iso`.
- Both packages were downloaded again from the public archive: their SHA-256 digests equal the
  built packages (`a53b71a3…be37` for `nex-core-local`, `7499888a…2382` for `nex-controller`).
