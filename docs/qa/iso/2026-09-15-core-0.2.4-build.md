# Nex Core 0.2.4 build and publication

Date: 2026-09-15. Same developer workstation and toolchain as the
[0.2.3 build](2026-09-15-core-0.2.3-build.md): `bash installer/build.sh` with the version
resolved from the changelog (`scripts/release-version.py --current --format both` → `0.2.4 0.2.4`),
then `packaging/controller/build.py` for the Controller package from the same
`dist/nex-source.tar.gz` the ISO embeds.

0.2.4 exists to carry the BUG-0187 downgrade-guard fix to hosts; 0.2.3 shipped the broken guard.
Built from the working tree, which at build time held the guard fix, its regression and the
version bump.

## The fix is in the artifacts, not just the tree

- Both packages contain the corrected guard: `usr/lib/nex/storage-downgrade-guard` in Core and
  `usr/local/lib/nex/storage-downgrade-guard` in the Controller package both carry the
  pseudo-action handling, and both still ship their `storage-format-v2` marker.
- Driven with APT's real two-line payload against the **real** 0.2.4 Core package and a
  version-2 storage state: the guard as shipped in 0.2.3 refuses it with the reported message
  (exit 1) — that is the operator's failure reproduced against this exact package — while the
  corrected guard accepts it (exit 0).
- After publication the Core package was downloaded from the public archive: its SHA-256 equals
  the built package, it declares `0.2.4`, it contains the corrected guard, and that downloaded
  guard accepts that downloaded package (exit 0).

## Publication

Published from the build workstation to the website host with the commands the release workflow
runs (`nex-apt-publish` for both packages, `release-publish.py` for the ISO), then verified over
public HTTPS: `/apt/dists/nex/InRelease` 200, the `Packages` index lists `nex-core-local 0.2.4`
and `nex-controller 0.2.4`, `/downloads/0.2.4/nex-core-0.2.4-amd64.iso.sha256` 200 and equal to
the built digest, and `/downloads/latest/` serves the 0.2.4 ISO. Retention used `--keep 5`, so no
earlier release was pruned; the tree holds `0.1.6~alpha1`, `0.1.8`, `0.2.2`, `0.2.3`, `0.2.4`.
The staging directory was removed.

## Not covered

- No boot or install test of this ISO: the 0.2.3 image was QEMU boot-tested, this one was not.
- No real Nex Core host was upgraded from the published archive. The guard was proven against the
  real packages and APT's real hook payload, but a full `apt` upgrade of a live Core, including
  its service restart, was not run.
- A host still carrying the 0.2.3 or earlier guard cannot install this release through `apt`
  without the recovery in [software updates](../../guide/software-updates.md), because the guard that
  decides an upgrade is the installed one. The reporting operator chose to reinstall instead.
- No forge release or `v0.2.4` tag exists; a later workflow run will rebuild and replace these
  artifacts.
