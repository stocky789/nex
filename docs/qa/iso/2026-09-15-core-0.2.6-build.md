# Nex Core 0.2.6 build and publication

Date: 2026-09-15. Same developer workstation and toolchain as the
[0.2.5 build](2026-09-15-core-0.2.5-build.md): the version resolved from the changelog
(`scripts/release-version.py --current --format both` → `0.2.6 0.2.6`), `bash installer/build.sh`
with `NEX_VERSION=0.2.6`, then `packaging/controller/build.py --source dist/nex-source.tar.gz
--version 0.2.6` for the Controller package from the same source archive the ISO embeds.

0.2.6 carries BUG-0193: a failed Controller GUI update no longer wedges every later update, the
update helper validates and safely consumes each request, and installing the package clears a
stuck update trigger. Built from commit `5c98a75` ("Fix Controller update-request wedge
(BUG-0193), release 0.2.6") with a clean tree; the tracked source still matched that commit when
the artifacts were checked.

## The fix is in the artifacts, not just the tree

- The Controller package's `/usr/local/lib/nex/apply-update` contains the BUG-0193 request
  validation (`only nex-controller can be updated`) and the `O_NOFOLLOW` progress and request
  handling.
- Before building, the full Python test suite (including `ControllerUpdateHelperRecoveryTests`),
  the documentation gate and the privacy test passed on the same commit. A Controller package
  built from the same helper and postinst was verified on a disposable systemd VM as recorded in
  the BUG-0193 ledger entry.

## Publication

Published by hand from the build workstation to the website host over SSH as the publishing
account, running the commands the release workflow runs: `sudo -n /usr/local/sbin/nex-apt-publish
<core-local.deb> <controller.deb>` for the signed APT archive, then `release-publish.py --iso <iso>`
for the download tree. Retention was `--keep 7`, so no earlier release was pruned; the tree holds
`0.1.6~alpha1`, `0.1.8`, `0.2.2`, `0.2.3`, `0.2.4`, `0.2.5` and `0.2.6`, with `latest` pointing
at `0.2.6`. The staging directory was removed.

Verified afterwards over public HTTPS, the same checks the workflow makes:

- `/apt/dists/nex/InRelease` → 200.
- `/apt/dists/nex/main/binary-amd64/Packages` → 200 and lists `nex-core-local 0.2.6` and
  `nex-controller 0.2.6`; both pool files return 200 with byte sizes equal to the built packages.
- `/downloads/0.2.6/nex-core-0.2.6-amd64.iso.sha256` → 200 and equals the built ISO digest.
- `/downloads/latest/` serves `nex-core-0.2.6-amd64.iso`.
- Both packages were downloaded again from the public archive: their SHA-256 digests equal the
  built packages (`cd0e5c99…6145` for `nex-core-local`, `7467a002…b0f8` for `nex-controller`).

## Not covered

- No boot or install test of this ISO.
- No real Controller or Nex Core host was upgraded from the published archive. A Controller already
  wedged by the 0.2.5 or earlier helper needs the manual recovery in the
  [software updates guide](../../guide/software-updates.md) before it can install 0.2.6.
- No forge release or `v0.2.6` tag exists; a later workflow run will rebuild and replace these
  artifacts.
