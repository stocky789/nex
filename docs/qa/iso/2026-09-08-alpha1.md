## Environment and reproduction

QEMU on an Intel host with KVM and nested virtualization. Each install uses a new 24 GiB sparse
file; no host block devices, live networks or physical machines. The temporary initrd supplies
disposable credentials and disk answers (absent from the shipping ISO); a test-only installed
service runs checks and powers off. Do not distribute the test disk as a host image.

This host's OVMF/KVM stalled at the EFI loader with both unmodified Debian and Nex media, so
UEFI menu checks use QEMU TCG, q35 and the builder-downloaded Debian OVMF: a working UEFI media
path, not KVM/OVMF compatibility on every host. BIOS install and the nested guest use KVM.

```sh
docker run --rm -v "$PWD:/work" --entrypoint dpkg-deb nex-iso-builder \
  -x /work/.cache/nex-iso/debs/ovmf_2025.02-8+deb13u1_all.deb \
  /work/.cache/nex-iso/qa-firmware
python3 tests/integration/iso-smoke.py dist/nex-core-0.1.0-alpha1-amd64.iso \
  --output .cache/nex-iso/qa-20260908-3 \
  --kernel .cache/nex-iso/stage/install.amd/vmlinuz \
  --initrd .cache/nex-iso/stage/install.amd/initrd.gz \
  --uefi-code .cache/nex-iso/qa-firmware/usr/share/OVMF/OVMF_CODE_4M.fd \
  --uefi-accel tcg
```

The runner refuses existing output directories. Commands, serial logs, captures and raw disk are
local under `.cache/nex-iso/qa-20260908-3/`, not committed.

## Coverage limits

- Nested guest proves kernel and BusyBox boot only: no full guest OS, guest networking or persistent guest-disk writes.
- Same-version `base-files` reinstall is not proof of future distro upgrades.
- Unverified: UEFI installation, Secure Boot, multiple-disk safety, physical Intel/AMD, SSH login, controller enrollment, restore/migration, full Phase 0/3 gates.
- Installed VM logged a `systemd-ssh-generator` AF_VSOCK CID warning with no vsock device; `ssh.service` was active. Chrony activity does not establish time sync.
